# lab3 점검 — 내 지시 프롬프트·저장소 지시문 점검, effort, 팀에 넘기기 (5단계 대본)

목표 2줄(1/5 메시지에 쓴다):
- 끝나면 내가 Claude에게 쓰는 지시 두 가지가 점검돼 있습니다 -- 평소 붙여 쓰는 지시 프롬프트는 다시 쓴 판으로 저장소에 남고, 저장소 안의 지시문(`CLAUDE.md`·내 스킬)은 낡은 문장 하나가 고쳐집니다.
- 그 상태로 README 첫 세 줄과 토큰이 빠진 커밋 1개까지 만들어, 팀에 넘길 수 있는 저장소가 됩니다.

턴 예산 7(출발점 1 · 정하기 ① 수용은 다음 명령으로 대신 · 점검 명령 1 · "정리해 줘" 1 · 지적 고르기 1 · 확정+예측 1 · 실행 1 · 확인 1 -- 수정 요청이 끼면 +1). 대상 스킬은 **참가자가 만든 것**이다: `.claude/skills/*-<팀>/`에 `.made-by-coach`가 있는 폴더(lab1·lab2 산출물, `python3 tools/make_skill.py list`). 없으면 예시 스킬 `meeting-notes`를 쓰되 1/5 둘째 줄에 "lab1 스킬이 아직 없어 예시 스킬로 합니다"를 한 번만 말한다. `usage.csv`는 대화를 끝낼 때마다 한 줄이 쌓인다(참가자에게는 "실행마다 한 줄이 쌓인다"로만). 커밋은 **5/5에서 네가 한다**(`git push`는 하지 않는다).

쓰는 말: "저장소 지시문 점검"(`/doctor prompt-audit`은 명령 이름 그대로, 첫 등장 때 "낡은 문장·없는 명령·서로 모순을 찾아 주는 점검"으로 한 번 설명). "감사", "린트", "cruft"는 쓰지 않는다.

## 1/5 출발점 (참가자 1턴) -- 평소 쓰는 지시 프롬프트 붙이기

```
단계 1/5 · 출발점
<목표 2줄>
오늘 점검하는 지시는 둘입니다 -- 내가 평소 Claude에게 붙여 쓰는 것, 그리고 이 저장소 안에 들어 있는 것.
먼저 평소 쓰는 지시 프롬프트를 그대로 붙여 주세요(3~10줄, 회사 비밀이 든 부분은 <...>로 바꿔도 됩니다).
준비한 것이 없으면 한 글자로 골라 주세요:
a) 회의록 정리 요청문 -- "회의록 정리해줘. 중요한 것만 보기 좋게…"   (추천: lab1에서 만든 스킬과 같은 주제)
b) 코드 리뷰 요청문 -- "이 코드 리뷰해줘. 문제 있으면 다 고쳐줘…"
c) 번역 요청문 -- "아래 글 영어로 번역해줘. 자연스럽게…"
```
a/b/c면 `docs/prompts/examples/`의 `meeting.md` / `review.md` / `translate.md` 코드 블록을 참가자 프롬프트로 쓴다. 기록 파일 1/5에 원문을 그대로 적는다(비밀로 가린 `<...>`도 그대로).

## 2/5 정하기 ① 내 프롬프트 진단 (참가자 턴 0~1) -- 바뀐 초안과 다음 명령을 한 메시지에

`.claude/skills/prompt-coach/SKILL.md`를 읽고 그 6개 축으로 **네가 직접** 진단한다(참가자에게 `/prompt-coach`를 치게 하지 않는다 -- 그 명령은 5/5의 "다음"에서 알려 준다). 화면에는 축 이름이나 표를 보이지 않고, `보완`인 것만 ≤3개를 **원문 인용 + 빠진 것 한 구절**로 보인다. 그 뒤 다시 쓴 프롬프트를 코드 블록으로, 마지막에 **저장소 지시문 점검 명령**을 그대로 붙여 "고칠 곳이 없으면 이 줄을 치세요"로 잇는다(확정만 받는 턴을 따로 두지 않는다).

```
단계 2/5 · 정하기
붙여 주신 지시에서 Claude가 알 수 없는 것 세 가지입니다.
- "중요한 것만" → 무엇이 중요한지(결정·할 일·미결처럼) 적혀 있지 않습니다
- "보기 좋게" → 어떤 모양인지(섹션 이름, 표인지 목록인지) 없습니다
- "신중하게 생각해서" → 요즘 Claude에는 효과가 없는 말입니다. 생각의 깊이는 문장이 아니라 설정(effort)으로 정합니다 -- 뒤에서 그렇게 합니다
다시 쓰면 이렇습니다.
<다시 쓴 프롬프트를 코드 블록으로 -- 참가자 말투 유지, 목적·입력·출력 모양·하지 말 것이 보이게, 사족 제거>
고칠 곳이 있으면 말해 주세요. 없으면 다음은 저장소 안의 지시문입니다. 아래 줄을 그대로 치세요 -- 낡은 문장·없는 명령·서로 모순을 찾아 주는 점검이고, 3분쯤 걸립니다. 결과는 영어로 길게 나오는데 읽지 않아도 됩니다. 끝나면 '정리해 줘'라고 하면 제가 세 개로 정리합니다.
/doctor prompt-audit CLAUDE.md .claude/skills/<내 스킬>/SKILL.md
```
참가자가 고치면 그 말을 반영해 초안을 다시 보이고 같은 명령 줄을 다시 붙인다(+1턴). 명령을 쳤으면 초안은 **수용**으로 기록한다. `<내 스킬>`은 대상 스킬 폴더 이름(예 `meeting-notes-cs`), 없으면 `meeting-notes`.

## 2/5 정하기 ② 저장소 지시문 점검 결과 → 고칠 것 하나 (참가자 2턴: 명령, "정리해 줘" 뒤 고르기)

점검 결과(영어 보고서: 가정 → 그룹별 요약 → 지적 표 `# / Location / Evidence / Pattern / Why / Confidence / Action` → 유지한 줄 → 제안 diff)가 대화에 나온 뒤 참가자가 "정리해 줘"라고 하면, 그 보고서의 지적 중 **Confidence가 High·Medium인 것**만 a/b/c로 올린다(보통 `CLAUDE.md`의 세 줄: "step by step… 신중하게" / 없는 `make lint` / `rules/testing.md`와 모순). Low는 맨 끝에 "참고(이번엔 안 고침): …" 한 줄. 보기 하나가 **원문 인용 + 왜 문제인지 한 줄 + 고치면 이렇게**를 담는다. 내 스킬 `SKILL.md`에 High·Medium이 있으면 그것도 보기에 넣는다(고치는 방법: `make_skill.py replace-line`).

```
단계 2/5 · 정하기
점검이 찍은 것 중 고칠 만한 세 개입니다. 우리 팀 CLAUDE.md에도 생길 법한 것 하나를 고르면 그 줄을 고칩니다.
a) CLAUDE.md 9행 "어떤 요청이든 답하기 전에 항상 step by step으로 깊고 신중하게 생각하라" → 요즘 모델에는 효과가 없는 말. 지우고, 깊이는 내 스킬의 effort로   (추천: 방금 내 프롬프트에서도 나온 것과 같은 종류)
b) CLAUDE.md 10행 "커밋 전 반드시 `make lint`를 실행한다" → 이 저장소에 Makefile이 없어 실행하면 실패. `npm test`로 바꾼다
c) CLAUDE.md 11행 "테스트는 수정 요청이 있을 때만 실행한다" → `.claude/rules/testing.md`의 "편집 뒤 항상 npm test"와 모순. 11행을 지운다(규칙 파일이 이긴다)
참고(이번엔 안 고침): `.env`를 읽지 말라는 줄은 맞는 규칙인데 이유가 없다고 함 / 내 스킬의 "git 명령은 사용하지 않는다" 줄
a처럼 한 글자로, 또는 다르게 고치고 싶으면 그 문장을 말해 주세요.
```
"그대로 둔다"나 다른 문장도 그대로 받아쓴다. **이런 경우?**(랩당 1회)는 여기서 겸한다 -- a를 고르면 "이 줄을 지우면 '신중하게'라는 의도는 어디서 보장되나요? → 내 스킬의 effort로, 다음 단계에서"를 보기 a의 설명으로 이미 말했으므로 따로 묻지 않는다.

**대체 경로**: 점검 명령의 결과가 "그 스킬을 쓸 수 없다/설정을 되돌리면 된다"는 두 문장이거나(번들 스킬 꺼짐), 명령을 모른다고 하거나(2.1.283 미만), 1분 안에 아무 결과가 없다고 참가자가 말하면 -- 위 a/b/c를 네가 `CLAUDE.md`를 읽어 바로 제시한다(원문 인용은 파일에서). 참가자에게 설정을 고치게 하지 않는다.

## 3/5 만들기 (참가자 1턴) -- 고치고, 저장하고, effort 추천과 README 초안

1. 고른 지적을 고친다: `CLAUDE.md`는 Edit(지우거나 고친다, 다른 줄은 건드리지 않는다). 내 스킬 본문이면 `python3 tools/make_skill.py replace-line .claude/skills/<내 스킬> "<원문 일부>" "<바뀐 줄 전체>"`(문장 하나만 뺄 때는 그 문장을 뺀 줄 전체를 new로).
2. 다시 쓴 프롬프트를 `docs/prompts/<팀>-<용도 영문 두 단어>.md`로 저장한다(예: docs/prompts/cs-meeting-summary.md -- 이름은 네가 짓고 묻지 않는다). 내용: `# <용도> 지시 프롬프트 -- <팀>` / `## 다시 쓴 것`(코드 블록) / `## 원문`(코드 블록) / `## 설정으로 옮긴 것`(prompt-coach 3번째 섹션 내용: 예 "신중하게 → 스킬 effort", 없으면 "- 없음").
3. 대상 스킬의 `effort:`는 네가 **추천값**을 정해 바로 넣는다: `python3 tools/make_skill.py set-frontmatter .claude/skills/<내 스킬> effort <값>`. 근거는 `usage.csv`의 그 스킬 실행 행(`effort`·`last_message_chars` 열) 1~2줄 -- 양식 채우기(회의록·보고·세 줄)는 `low`, 근거를 더 찾아야 하는 일만 `medium`. `usage.csv`가 없으면 그 열은 말하지 않는다.
4. `README.md` 제목 바로 아래 세 줄 **초안**: `docs/worksheets/lab1.md`·`lab2.md`를 읽어 (1) 누구를 위한 저장소 -- `<팀> Claude Code 저장소` (2) 첫 명령 -- 시작 명령(`bash tools/setup.sh` 줄) 뒤 `/<lab1 스킬> <파일>` (3) 하지 말 것 -- lab1·lab2에서 정한 실수 줄 중 하나. 기존 첫 세 줄은 그 아래로 내린다. 기록이 없으면 (2)(3)은 대상 스킬의 머리 부분과 실수 줄에서 추린다.
5. 메시지(25줄 이내):
```
단계 3/5 · 만들기
고친 파일: CLAUDE.md, docs/prompts/cs-meeting-summary.md(새 파일), .claude/skills/meeting-notes-cs/SKILL.md, README.md
| 전 | 후 |
|---|---|
| CLAUDE.md 9행 "…step by step으로 깊고 신중하게 생각하라." | 바뀜: (삭제) |
| 내 프롬프트 "회의록 정리해줘. 중요한 것만…" | 바뀜: docs/prompts/cs-meeting-summary.md에 다시 쓴 판 + 원문 저장 |
| meeting-notes-cs effort: (없음) | 바뀜: effort: low  (추천 -- 양식 채우기, 지난 실행 2회 모두 low로 790자) |
| README 1~3행 "Claude Code 슈퍼랩 저장소 / 내 반복 작업을… / 판단은…" | 바뀜: cs팀 Claude Code 저장소 / 시작 명령 뒤 `/meeting-notes-cs <녹취>` / 담당자가 없으면 '미정'  (제안) |
검사: meeting-notes-cs 통과 6/6
effort와 README 세 줄은 제가 고른 추천입니다. 맞으면 '확정'이라 하면서 예측 하나를 덧붙여 주세요: 이 effort로 내 스킬을 다시 돌리면 결과 길이가 지금보다 늘지 / 줄지 / 비슷할지. 예: `확정, 비슷`. 고칠 곳이 있으면 그 줄만 고쳐 말해 주세요.
```
`(추천)`·`(제안)`이 붙은 줄은 참가자가 바꿀 수 있다. 바꾸면 그 말을 그대로 넣고 전/후 표를 다시 보인다(+1턴). 예측 없이 "확정"만 오면 예측은 `미기록`, 다시 묻지 않는다. 기록 파일 3/5에 전/후와 줄마다 이유(참가자 말 인용, 추천은 `추천 수용`)를 적는다.

묻지 않는다. 5줄 이내. 대상 스킬을 샘플로 돌릴 명령 하나(회의록이면 `samples/meeting-2026-10-02.txt`, 주간보고면 `samples/weekly-memo.md`, 스탠드업·PR 설명은 인자 없음):

단계 4/5 · 실행
/meeting-notes-cs samples/meeting-2026-10-02.txt
결과가 나오면 '확인해 줘'라고 해 주세요.

결과를 받으면 길이(글자 수)를 세어 3/5의 예측과 비교할 준비를 한다. `usage.csv`가 있으면 마지막 행의 `effort`·`last_message_chars`도 읽는다.

## 5/5 확인 (참가자 1턴) -- 커밋은 네가 한다

1. `git status --short`로 바뀐 파일을 확인한다(`settings.local.json`·`usage.csv`가 **없음**을 확인 -- `.gitignore`가 뺀다). 저장소의 `.env`는 가짜 값이 든 연습 파일이라 커밋에 있는 것이 맞다 -- 언급하지 않는다. `CLAUDE.md`의 고르지 않은 지적 줄(`make lint` 등)은 따르지도 언급하지도 않는다.
2. `git add -A` → `git commit -m "feat: <팀> team Claude Code repo -- prompts, CLAUDE.md fix, effort"` → `git show --stat --oneline HEAD`. 참가자에게 커밋하라고 하지 않는다. `git push`는 하지 않는다(원격은 참가자 팀 저장소다).
3. 메시지(12줄 이내):
```
단계 5/5 · 확인
## 검사
| 항목 | 결과 |
|---|---|
| 고른 지적 줄이 CLAUDE.md에서 바뀌었다 | 통과 -- 9행 "step by step" 없음 |
| 다시 쓴 프롬프트가 docs/prompts/에 있다 | 통과 -- docs/prompts/cs-meeting-summary.md |
| 내 스킬 effort = 정한 값 | 통과 -- effort: low |
| 예측 → 실제 (결과 길이) | 비슷 → 812자 → 790자 |
| README 첫 세 줄 = 확정한 세 줄 · 커밋에 토큰 파일(settings.local.json) 없음 | 통과 -- a1b2c3d (4 files) |
다음: 새 지시를 쓸 때는 `/prompt-coach "…"`로 먼저 진단받고, 저장소 지시문은 분기마다 `/doctor prompt-audit CLAUDE.md`로 점검하세요. 이 커밋을 팀 저장소 주소로 올리는 것은 강사가 안내합니다.
```
확인하지 못한 항목은 `미확인`으로 둔다(통과로 쓰지 않는다). 참가자에게 할 일을 남기지 않는다. 기록 파일 5/5에 검사 표와 추적표(파일 줄 ↔ 2/5의 참가자 말)를 적는다.
