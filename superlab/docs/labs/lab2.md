# Lab 2 — 사내 API를 스킬로 자동화하기

## 목표

끝나면 "사내 시스템을 조회해 우리 팀 양식으로 정리"하는 스킬이 하나 생깁니다. `/이름` 한 번이면 승인 창 없이 보고가 나옵니다. 조회(읽기만)는 승인 없이 되고, 신청(바꾸기)은 승인 창이 뜨는 이유를 설명할 수 있게 됩니다.
산출물: `.claude/skills/<데이터>-report-<팀>/SKILL.md`(예: `leave-report-cs`), 결정 기록 `docs/worksheets/lab2.md`.

시작 명령은 하나입니다.

```text
/workshop-coach lab2
```

## 파일 구조

```text
superlab/
├── .claude/
│   ├── settings.local.json           토큰과 API 주소 — 준비 단계의 setup.sh가 저장, 커밋되지 않음
│   ├── settings.json                 팀 설정 — 조회 스크립트는 승인 없이, 신청(POST)은 승인 창
│   └── skills/
│       ├── leave-report/             예시 스킬 — "조회 결과를 양식으로 정리"의 본보기 (조회 명령 한 줄이 들어 있음)
│       └── <데이터>-report-<팀>/      ★ 이 랩에서 코치가 만드는 내 스킬 (예: leave-report-cs/)
├── tools/
│   ├── hr_fetch.py                   사내 API 조회 스크립트 — me | leave | requests | deploys (읽기만, JSON으로 출력)
│   ├── lab_server.py                 공용 API가 꺼졌을 때 쓰는 로컬 대체 서버
│   └── <시스템>_fetch.py             시스템 이름을 바꾸면 코치가 hr_fetch.py를 복제해 만드는 파일
├── reports/                          보고를 파일로 남기기로 했다면 여기에 (승인 창이 한 번 뜬다)
└── docs/worksheets/lab2.md           ★ 결정 기록
```

실습 시스템(공용 사내 API)에는 세 종류의 데이터가 있습니다 -- 연차 현황, 신청 내역, 배포 상태. 토큰별로 팀이 다르므로 옆자리와 숫자가 다릅니다.

## 5단계

참가자가 치는 것은 **답 ≤8번과 실행 명령 한 줄**입니다.

| 단계 | 코치가 하는 것 | 내가 답하는 것 |
|---|---|---|
| 1/5 출발점 | 실습 시스템의 **실제 데이터** 세 종류를 두 줄씩 보여 준다(연차 현황 / 신청 내역 / 배포 상태) | a~c 중 한 글자 |
| 2/5 정하기 | 고른 데이터를 예시 양식으로 정리한 **지금 결과**를 보여 주고 "가장 먼저 바꿀 곳 하나"를 묻는다. 그다음 "어느 날 아침 실습 시스템이 꺼져 있어 조회가 실패했습니다. 보고에 무엇이 나와야 하나요?" | 바꿀 곳(말로), 실패 때 보고 내용 |
| 3/5 만들기 | 스킬 폴더를 만들고 전/후 표를 보여 준다. 조회를 승인 없이 돌리게 하는 설정 줄은 스킬 파일 안에(기본값 -- 스킬을 복사하면 함께 간다) | `확정, <예측>` 또는 한 줄 수정 |
| 4/5 실행 | 실행 명령 한 줄(`/<내 스킬>`) | 그 줄을 그대로 친다 |
| 5/5 확인 | 검사 표(양식·실패 때 문구·승인 창 없이 돌았나·예측 → 실제)와 다음 한 줄 | "확인해 줘" |

1단계 메시지는 이렇게 시작합니다.

```text
단계 1/5 · 출발점
끝나면 "사내 시스템 조회 → 우리 팀 양식으로 정리"하는 스킬이 하나 생깁니다. /이름 한 번이면 승인 창 없이 보고가 나옵니다.
조회(읽기만)는 승인 없이 되고, 신청(바꾸기)은 승인 창이 뜹니다. 오늘 만드는 것은 조회 보고입니다.
지금 실습 시스템에 들어 있는 데이터는 세 가지입니다.
a) 연차 현황: han(sre) 잔여 3 / 사용 12, lee(pm) 잔여 3 / 사용 12 … → 팀 전원의 잔여·사용 / 운영 회의나 인력 계획을 보는 분   (추천)
b) 신청 내역: 지금 0건 → 우리 팀이 넣은 신청과 상태(pending(대기) 등) / 결재하거나 일정을 조정하는 분
c) 배포 상태: order-api v6.6.6 healthy(정상), web-front v9.3.6 degraded(이상) … → 서비스별 버전·상태 / 개발자, 아침 점검
이 랩에서 가장 먼저 해 보고 싶은 것은 어느 것인가요? a처럼 한 글자로 답해 주세요.
```

## 코치 없이 직접 만들 때

회사 시스템에 붙일 때 아래 프롬프트를 그대로 붙이고 `<...>`만 채우세요. 조회 스크립트 한 개와 스킬 한 개가 생깁니다.

```text
사내 시스템 <시스템 이름>을 조회해 팀 보고로 정리하는 스킬을 만들어 줘.
- 조회 스크립트 tools/<시스템>_fetch.py: tools/hr_fetch.py 를 본보기로. 읽기(GET)만 하고, 주소는 <API 주소>, 토큰은 환경 변수 <토큰 변수 이름>에서 읽어(코드에 적지 마). 결과는 JSON으로 출력하고, 실패하면 error 필드가 든 JSON을 출력해.
- 스킬 .claude/skills/<데이터>-report-<팀>/SKILL.md: 첫 줄에서 그 스크립트의 결과를 자동으로 넣고(명령 하나만), 그 명령의 사전 승인을 스킬 안에 넣어서 /<데이터>-report-<팀> 한 번에 승인 창 없이 보고가 나오게 해.
- 보고 양식: 제목 <제목>, 표의 열은 <열 1> | <열 2> | <열 3> 순서, <강조 규칙, 예: 잔여가 3일 이하면 굵게>.
- 조회가 실패하면 <예: 원인 한 줄과 "시스템 담당자에게 확인" 한 줄>만 출력해.
- JSON에 없는 이름·숫자는 만들지 마. 바꾸기(POST)는 넣지 마.
만든 뒤 스크립트만 따로 돌려 JSON이 나오는지, /<데이터>-report-<팀>이 승인 창 없이 보고를 내는지, 결과의 이름·숫자가 JSON과 같은지 확인해서 보고해 줘.
```

승인 창이 뜨면 사전 승인 줄이 빠진 것이고, 보고에 JSON에 없는 행이 보이면 마지막 금지 줄이 지켜지지 않은 것입니다.

## 공용 API를 쓸 수 없을 때

로컬 대체 서버를 켜고, 저장된 주소를 로컬 주소로 바꾼 뒤 Claude Code를 다시 시작합니다. 스킬은 그대로 동작합니다. 공용 API로 되돌릴 때는 준비 단계의 `setup.sh` 줄을 다시 실행합니다.

```bash
python3 tools/lab_server.py
LAB_API_BASE=http://127.0.0.1:8787 bash tools/setup.sh
claude
```
