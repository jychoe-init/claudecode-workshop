## 랩 공통 -- 코치가 하는 일

- 매 메시지 첫 줄이 `단계 N/5 · 이름`입니다. 참가자가 "지금 어디예요?"라고 하면 그 줄을 보라고 합니다.
- **결정은 참가자, 파일은 코치.** 참가자는 결과물을 보고 말로 고치고(`a`처럼 한 글자, 또는 "비고는 빼"), 코치가 스킬 폴더·설정·기록을 만듭니다. 참가자가 복사하거나 편집하는 단계는 없습니다. "니가 해"라고 해도 코치는 거절하지 않습니다 -- 추천을 적용하고 `추천 수용`으로 기록합니다.
- 결정 기록(`docs/worksheets/`의 lab1.md·lab2.md·lab3.md)에 참가자 말이 그대로 적히고, 전/후 표에서 바뀐 줄은 `바뀜:`으로 표시됩니다. 순회할 때 "고른 방식" 열이 전부 `추천 수용`인 참가자에게는 결과물에서 마음에 안 드는 줄 하나를 말해 보라고 권합니다.
- 4/5 실행에서 참가자가 치는 것은 코치가 준 명령 한 줄뿐입니다. 실패하면 코치가 고쳐 같은 명령을 다시 줍니다.

## 랩별 시연과 순회 포인트

### lab1 (16분)
- 시연 2분: `/meeting-notes samples/meeting-2026-10-02.txt` 결과를 보여 주고 "결과 모양은 `template.md` 하나가 정한다 -- 그 파일을 바꾸면 결과가 바뀐다"를 말합니다. 녹취 22행의 테스트용 지시문이 기록으로만 남은 것을 짚습니다.
- 순회: 2/5에서 빈칸 앞에 멈춘 참가자에게 "결과물에서 바꿀 곳 하나만 말하세요". 바꿀 곳이 많으면 미리 만든 양식(`templates/`, 주간보고 3종·회의록 3종·스탠드업·PR 2종씩)으로 통째 교체(보기 b)를 권합니다.

### lab2 (16분)
- 시연 3분: 공용 API 문서 페이지, `/leave-report` 결과(승인 창 없음), `tools/hr_mcp.py`로 연차 **신청**을 시켜 승인 창이 뜨는 것. "조회는 승인 없이, 바꾸기는 승인" 한 문장.
- 순회: 보고가 비어 있으면 시작 명령을 다시 실행했는지(`settings.local.json`에 토큰·주소) 확인합니다. 옆자리와 숫자가 다른 것은 토큰별 팀이 다르기 때문입니다.

### lab3 (12분)
- 시연 1분: 모호한 프롬프트 하나(`docs/prompts/examples/meeting.md`)를 `/prompt-coach "…"`에 넣은 결과(빈 칸 지적 + 다시 쓴 판), 그리고 미리 돌려 둔 `/doctor prompt-audit CLAUDE.md` 결과의 지적 표. "결과는 영어로 길게 나오지만 코치가 세 개로 정리해 준다"를 말합니다.
- 순회: 점검 명령은 3분쯤 걸립니다 -- 그동안 참가자가 기다리게 두지 말고 다시 쓴 프롬프트 초안을 읽게 합니다. 프롬프트를 안 가져온 참가자는 보기 a/b/c. 1분 안에 결과가 없거나 "그 스킬을 쓸 수 없다"가 나오면 코치가 결함 세 줄을 바로 제시합니다(대체 경로).
- 커밋은 코치가 합니다(`git push`는 하지 않음). `git show --stat`에 `settings.local.json`·`usage.csv`가 없는 것을 참가자 화면에서 확인합니다. 저장소의 `.env`는 가짜 값이 든 연습 파일이라 커밋에 있는 것이 맞습니다.

## 막히는 지점과 대체 방법

| 막히는 지점 | 대체 방법 |
|---|---|
| 공용 API가 응답하지 않음 | `python3 tools/lab_server.py`를 실행하고 `LAB_API_BASE=http://127.0.0.1:8787 bash tools/setup.sh`로 저장된 주소를 바꾼 뒤 Claude Code를 다시 시작합니다. 같은 스킬이 그대로 동작합니다. 공용 주소로 되돌릴 때는 준비 단계의 `setup.sh` 줄을 다시 실행합니다. |
| 시작 명령을 안 치고 `claude`를 열었음 | 토큰이 없어 lab2 조회가 `no_token`으로 실패합니다. `/exit` 뒤 시작 명령 줄을 실행하고 다시 엽니다. |
| Claude Code가 2.1.283 미만이거나 `/doctor prompt-audit`이 "쓸 수 없다"고 함 | 코치가 대체 경로로 결함 세 줄을 바로 제시합니다. 점검 결과 모양은 강사 화면으로 보여 줍니다. |
| 점검 명령이 너무 오래 걸림 | 파일을 하나로 줄입니다: `/doctor prompt-audit CLAUDE.md`. 범위를 적지 않으면 저장소 전체(코치 대본 포함)를 읽어 더 오래 걸립니다. |
| 코치가 파일을 못 쓰고 승인 창이 뜸 | 폴더 신뢰 대화상자를 승인했는지(`/status`에 프로젝트 설정이 보여야 함) 확인합니다. 신뢰 전에는 프로젝트 allow 규칙이 적용되지 않습니다. |
| MCP가 연결되지 않음 | 시연은 `/leave-report` 결과로 이어 갑니다. 참가자 랩에는 MCP가 필요하지 않습니다. |
| 시간이 부족함 | lab2 시연을 1분으로, lab3 점검 범위를 `CLAUDE.md` 하나로. 완료 기준(labNa/labNb)은 유지합니다. |
