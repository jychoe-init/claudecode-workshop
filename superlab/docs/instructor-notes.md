# Ch4 슈퍼랩 — 강사 노트

세 랩은 "누가 만드나"의 사다리입니다. lab1은 코치가 만들고 참가자가 결정만 합니다. lab2는 강사가 준 좋은 프롬프트 한 장으로 참가자가 도구(`prompt-coach`)를 만듭니다. lab3는 참가자가 요청문부터 직접 써서 그 도구로 다듬고 휴가 스킬을 만듭니다. 모델은 Claude Opus 5.5(저장소 `settings.json`), effort는 어느 랩에서도 바꾸지 않습니다.

## 수업 전 준비

- [ ] 공용 API: 배포 주소의 문서 페이지(`/`)와 `/v1/me`, `/v1/leave`, `/v1/leave/requests`, `/v1/mail/planning/sent`가 공통 토큰으로 응답하는지 확인합니다. 주소와 토큰은 참가자용 HTML 안내 자료에만 적고 이 저장소(공개)에는 적지 않습니다.
- [ ] 참가자 시작 명령 한 줄을 화면에 띄웁니다(README 시작 절과 같은 줄). `setup.sh`가 토큰·주소를 `settings.local.json`에 저장하고 커밋되지 않습니다. 저장소 폴더 신뢰 대화상자를 승인해야 프로젝트 설정(승인 규칙)이 적용됩니다 -- `/status`에 프로젝트 설정이 보여야 합니다.
- [ ] `/mcp`에 `hr`가 연결되어 있는지 참가자 화면에서 확인합니다. lab3가 이 연결을 씁니다(lab2는 쓰지 않음).
- [ ] `claude --version` 2.1.283 이상, Node.js, Python 3.
- [ ] 강사 세션 리허설: `/workshop-coach lab1` 첫 메시지 · lab2 주는 프롬프트를 붙여 `prompt-coach` 생성(5~8분) · `docs/solutions/lab3/leave-request/`를 설치해 `/leave-request` 조회(승인 없음)·신청(승인 창)·거절(내역에 없음).
- [ ] **참가자 조건 재현**: 강사 머신에 샌드박스 자동 허용이나 `defaultMode: auto`가 켜져 있으면 승인 창 동작이 참가자와 달라집니다. 시연 세션은 `claude --settings '{"sandbox":{"enabled":false},"permissions":{"defaultMode":"default"}}'`로 엽니다.
- [ ] 권한 규칙은 **deny → ask → allow** 순서입니다. `mcp__hr__request_*`가 ask이므로 참가자 스킬이 머리 부분에 무엇을 적어도 신청에는 승인 창이 뜹니다. 이 설정을 바꾸지 마세요 -- lab3의 "전송 직전 취소"가 이 승인 창입니다.
- [ ] 참가자 사전 준비물은 없습니다.

## 랩별 시연과 순회 포인트

### lab1 (코치 있음)
- 시연 2분: `/meeting-notes samples/meeting-2026-10-02.txt` 결과를 보여 주고 "결과 모양은 `template.md` 하나가 정한다"를 말합니다. 녹취 22행의 테스트용 지시문이 기록으로만 남은 것을 짚습니다.
- 순회: 2/5에서 빈칸 앞에 멈춘 참가자에게 "결과물에서 바꿀 곳 하나만 말하세요". 미리 만든 양식(`templates/`)으로 통째 교체를 권합니다.
- 코치는 셸 조회를 명령 하나씩 따로 돌립니다. 첫 화면에 `Error: Exit code`가 보이면 코치가 명령을 묶은 것입니다 -- 결과에는 영향이 없지만 보고해 주세요.

### lab2 (코치 없음 -- 주는 프롬프트)
- 시연 1분: `docs/labs/lab2-prompt.md`를 화면에 띄우고 "이 한 장이 좋은 요청문의 모양입니다 -- 목적·입력·판정·출력·하지 않는 것·확인이 다 있습니다. 이걸 그대로 붙입니다"라고 말합니다. 생성 과정을 시연하지 않습니다(5~8분 걸림).
- 순회: 모델이 자체 시험 표를 안 내고 끝났으면 "확인 절대로 샘플 3개를 돌려 표를 보여 줘" 한 줄. 샘플 하나가 계속 실패하면 그 샘플 파일 끝의 "기대 지적"을 함께 읽고 어느 절(판정/질문/출력)이 비었는지만 짚어 줍니다 -- 샘플 문장을 SKILL.md에 박아 넣는 것은 막습니다.
- 참가자가 직접 호출(3단계)할 때 질문 선택지가 실제로 뜨는지 봅니다. 뜨지 않으면 SKILL.md의 질문 절이 AskUserQuestion을 쓰라고 되어 있는지 확인합니다.

### lab3 (코치 없음 -- 요청문부터 직접)
- 시연 1분: 샘플 01의 나쁜 초안을 `/prompt-coach`에 넣어 질문이 뜨는 장면까지만. "이 질문에 답하면 요구 사항이 됩니다."
- lab3에는 요구 사항 문단이 없습니다 -- 표(생성 에셋·호출·연결·완료 기준)와 1단계에서 본 응답이 스펙입니다. 누가 쓰나·안 되는 일·결과 모양은 참가자가 `/prompt-coach` 질문에 답해 정합니다 -- 좋은 답의 예: 팀장이 현황표를 본다 / 날짜 누락·잔여 초과·전송 직전 취소 / 표. 날짜를 "10월 7일"처럼 쓰는 것과 직원 이름이 필요한 것은 실행에서 부딪히게 두고, 부딪힌 참가자는 내 도구로 한 번 더 다듬게 합니다.
- 순회: 초안을 못 쓰는 참가자에게는 "hr 도구로 연차 조회하고 신청하는 스킬 leave-request를 만들어 줘" 한 줄로 충분하다고 말합니다. 5단계 ③ **거절**을 건너뛰는 참가자가 많습니다 -- 승인 창에서 '아니오'를 눌러 보게 하고, 신청 내역에 그 건이 없는 것을 확인시킵니다. 참가자가 정한 '안 되는 일'이 어디서 막혔는지는 정답이 없습니다.
- 6단계 '팀에 넘기기'는 공식 배포 방식 셋(저장소 `.claude/skills/` 커밋 / 플러그인 / 관리 설정) 중 첫째입니다. 참가자는 한 줄만 시키고, 확인은 완료 기준 lab3b(이름·경로·토큰 없음, README 세 줄, 토큰 파일 없는 커밋)로 합니다. 같은 이름의 개인 스킬이 프로젝트 스킬보다 우선한다는 것은 받는 쪽 주의 사항입니다.
- 커밋은 참가자가 모델에게 시킵니다. `git show --stat`에 `settings.local.json`·`usage.csv`가 없는 것을 참가자 화면에서 확인합니다(`.gitignore`가 막습니다). 저장소의 `.env`는 테스트 값이 든 연습 파일이라 커밋에 있는 것이 맞습니다.
- `/doctor prompt-audit`은 참가자 과제가 아닙니다. 시간이 남으면 마무리에 1분: "제품 기능도 지시 파일을 점검합니다 -- 구형 모델 전제 지시, 없는 파일·명령 참조, 서로 모순되는 파일 세 가지를 찾아 수정안 리포트를 냅니다(2.1.283+, 적용은 요청할 때만)." 인용은 릴리스 노트·Commands 레퍼런스·Memory 문서 범위 안에서만.

## 막히는 지점과 대체 방법

| 막히는 지점 | 대체 방법 |
|---|---|
| 공용 API가 응답하지 않음 | `python3 tools/lab_server.py`를 실행하고 `LAB_API_BASE=http://127.0.0.1:8787 bash tools/setup.sh`로 저장된 주소를 바꾼 뒤 Claude Code를 다시 시작합니다. MCP `hr`가 로컬 서버를 부릅니다. 공용 주소로 되돌릴 때는 준비 단계의 `setup.sh` 줄을 다시 실행합니다. |
| 시작 명령을 안 치고 `claude`를 열었음 | 토큰이 없어 lab3 조회가 "LAB_TOKEN이 없습니다"로 실패합니다. `/exit` 뒤 시작 명령 줄을 실행하고 다시 엽니다. |
| `/mcp`에 `hr`가 없음 | `.mcp.json`이 프로젝트에 있는지, 프로젝트 신뢰를 승인했는지 확인합니다. lab2는 MCP 없이 진행되므로 lab2를 먼저 끝내고 돌아옵니다. |
| lab2 생성이 10분을 넘김 | 모델이 자체 시험을 반복하고 있는 것입니다. 표가 두 번 나왔으면 멈추게 하고 3단계(직접 호출)로 넘어갑니다. |
| `/prompt-coach` 응답이 아무 설명 없이 거절됨(refusal) | 참가자 초안이나 샘플에 "생각한 과정을 적어 줘"처럼 **모델의 내부 추론을 보여 달라는 문장**이 있는지 봅니다. 그 뜻의 문장은 단어를 바꿔도 안전장치(`reasoning_extraction`)가 응답을 막습니다 -- 그 문장을 빼고 다시 넣게 합니다. 기준 문서 `docs/references/opus-5-5-prompting.md`에 규칙이 있습니다. |
| 승인 창이 조회에서도 뜸 | 프로젝트 신뢰 전이라 allow 규칙이 적용되지 않은 것입니다. 신뢰를 승인하고 다시 실행합니다. |
| 승인 창이 신청에서 안 뜸 | `.claude/settings.json`이 바뀐 것입니다. `git diff .claude/settings.json`으로 확인하고 되돌립니다. |
| 시간이 부족함 | lab1을 결정 1개로, lab3의 '다시 보기'를 자율 실습으로. 완료 기준은 유지합니다. |

## 마무리 (3분)

체크리스트 세 항목 -- **Repeat** 내 반복 작업 하나가 양식과 실수 방지가 박힌 스킬이 됐는가(lab1) / **Shape** 요청문을 진단하고 묻고 다시 쓰는 내 도구가 있고, 그 도구로 내 요청문을 다듬어 봤는가(lab2·3) / **Connect·Share** 사내 시스템 조회·신청 스킬이 돌고 "조회는 승인 없이, 바꾸기는 승인"을 설명할 수 있으며 토큰 없는 커밋을 만들었는가(lab3). 다음 단계로 매일 아침 사람 없이 돌리는 것(`claude -p`, 다음 장)과 `/doctor prompt-audit`을 안내합니다.
