# Lab 1 — 내 반복 작업을 스킬로

## 목표
- 회사에서 바로 쓸 스킬 하나를 만듭니다.
- 입력, 출력 양식, 금지를 직접 결정합니다.
- 실행 결과가 내 결정과 같은지 확인합니다.

## 시작 명령

```text
/workshop-coach lab1
```

## 출발점 다섯 가지

코치가 가장 먼저 "어느 출발점에서 시작할까요"를 묻습니다. 보기는 이 다섯 가지입니다. 슈퍼랩 예시 스킬은 처음 보는 것이니, 결정 전에 하나를 실행해 보세요.

| 보기 | 넣는 것 → 나오는 것 | 맞는 사람 | 지금 실행해 보기 |
|---|---|---|---|
| a) 회의록 `meeting-notes` | 회의 녹취 txt → 결정사항·액션 아이템(담당·기한)·미결 | 회의가 많은 사람. 샘플 녹취가 있어 바로 볼 수 있습니다 | `/meeting-notes samples/meeting-2026-10-02.txt` |
| b) 주간보고 `weekly-report` | 이번 주 보낸 메일·일정(자동으로 읽음) → 성과·다음 주 계획·이슈 | 매주 보고서를 쓰는 사람 | `/weekly-report` |
| c) 스탠드업 `standup` | 어제 커밋(자동으로 읽음) + 오늘 할 일 → 어제·오늘·막힘 | 개발자 | `/standup "오늘 할 일"` |
| d) 개발자 주간보고 `weekly-report-dev` | 지난 7일 커밋(자동으로 읽음) + 막힌 것 → 한 일·다음 주 계획·이슈 | 개발자 | `/weekly-report-dev "막힌 것"` |
| e) 새로 만들기 `docs/templates/skill-blank/` | 빈 틀. 입력·출력·금지 자리만 있습니다 | 반복 작업이 분명한데 위 넷에 없는 사람 | (실행할 것 없음) |

a~d는 이미 동작하는 스킬을 복사해 `template.md`(출력 양식)와 지시문 두세 줄만 내 것으로 고칩니다. 대부분은 여기서 시작합니다. e는 frontmatter부터 직접 채웁니다. 어느 쪽이든 남는 파일은 `.claude/skills/<내이름>/SKILL.md`(+ `template.md`)입니다.

## 1. 세 가지 결정

**참가자가 하는 일**
- 출발점 하나를 고릅니다(위 표의 a~e).
- 양식(결정 1)은 **방금 본 결과물에서 시작**합니다. 코치가 결과의 뼈대를 보여 주고 "그대로 보내도 되나요? 가장 먼저 바꿀 곳 하나만"을 묻습니다. 한 곳을 바꾸면 바뀐 결과를 다시 보여 주고 "다음으로 바꿀 곳?"을 묻습니다. 보통 두세 번이면 끝나고, 확정하면 `template.md`의 전/후를 나란히 보여 줍니다.
- 바꿀 곳이 많으면 미리 만든 팀 양식으로 통째 바꿀 수 있습니다: 각 출발점 폴더의 `templates/` 안에 있습니다(주간보고: 경영진 보고형 `exec.md`, 개발팀형 `dev.md`, 운영형 `ops.md` / 회의록: 임원 회의형 `exec.md`, 프로젝트 정례형 `project.md`, 15분 회의형 `short.md` / 스탠드업: 2종 / 개발자 주간보고: 스프린트형 `sprint.md`, 릴리스 노트형 `release.md`). 바꾼 뒤 다시 한 곳씩 고칠 수 있습니다.
- 입력 소스와 호출 방식을 정합니다(결정 2).
- 만들면 안 되는 내용 하나를 정합니다(결정 3).

**Claude에게 일반 요청으로 시키는 일**
- 선택한 출발점을 내 스킬 폴더로 복사하게 합니다.
- 필요한 frontmatter와 본문 골격을 만들게 합니다.
- 결정하지 않은 내용은 추가하지 않게 합니다.

## 2. 직접 작성하고 진단

**참가자가 하는 일**
- `template.md`를 결정 1 전/후의 "후"대로 고칩니다. 미리 만든 양식으로 바꿨으면 먼저 `cp .claude/skills/<내이름>/templates/<양식>.md .claude/skills/<내이름>/template.md`.
- `SKILL.md`의 `description`, `argument-hint`, 입력 줄, 금지 줄을 채웁니다.
- 작성한 스펙을 `/prompt-coach`로 진단하고 모호한 한 줄을 고칩니다.

**Claude에게 일반 요청으로 시키는 일**
- 보일러플레이트와 스텁을 작성하게 합니다.
- YAML과 파일 참조가 맞는지 읽기 전용으로 확인하게 합니다.

## 3. 예측하고 실행

실행 전에 두 가지를 적습니다.
1. 첫 결과에 섹션이 몇 개 나올지 예측합니다.
2. 입력 파일 안의 명령형 문장이 어떻게 다뤄질지 예측합니다.

```text
/<내이름> samples/meeting-2026-10-02.txt
```

자기 메모를 쓴다면 마지막 경로만 바꿉니다.
