# Lab 1 — 내 반복 작업을 스킬로

## 목표
- 월요일에 바로 쓸 스킬 하나를 만듭니다.
- 입력, 출력 양식, 금지를 직접 결정합니다.
- 실행 결과가 내 결정과 같은지 확인합니다.

## 시작 명령

```text
/workshop-coach lab1
```

## 길 선택

| 길 | 출발점 | 잘 맞는 경우 | 남는 파일 |
|---|---|---|---|
| A · 변형 | `meeting-notes`, `weekly-report`, `standup`, `pr-desc` | 기존 예시를 우리 팀 양식으로 바꾸고 싶을 때 | `.claude/skills/<내이름>/SKILL.md`, `template.md` |
| B · 신규 | `docs/templates/skill-blank/` | 다른 반복 작업과 입력이 이미 분명할 때 | `.claude/skills/<내이름>/SKILL.md`, 필요하면 `template.md` |

## 1. 세 가지 결정

**참가자가 하는 일**
- 길 A 또는 B를 고릅니다.
- 독자와 출력 양식을 정합니다.
- 입력 소스와 호출 방식을 정합니다.
- 만들면 안 되는 내용 하나를 정합니다.

**Claude에게 일반 요청으로 시키는 일**
- 선택한 출발점을 내 스킬 폴더로 복사하게 합니다.
- 필요한 frontmatter와 본문 골격을 만들게 합니다.
- 결정하지 않은 내용은 추가하지 않게 합니다.

## 2. 직접 작성하고 진단

**참가자가 하는 일**
- `template.md`의 섹션 이름과 순서를 고칩니다.
- `SKILL.md`의 `description`, `argument-hint`, 입력 줄, 금지 줄을 채웁니다.
- 작성한 스펙을 `/prompt-coach`로 진단하고 모호한 한 줄을 고칩니다.

**Claude에게 일반 요청으로 시키는 일**
- 보일러플레이트와 스텁을 작성하게 합니다.
- YAML과 파일 참조가 맞는지 읽기 전용으로 확인하게 합니다.

## 3. 예측하고 실행

실행 전에 두 가지를 적습니다.
1. 첫 결과에 섹션이 몇 개 나올지 예측합니다.
2. 입력 파일 안의 명령형 문장이 어떻게 다뤄질지 예측합니다.

```text
/<내이름> samples/meeting-2026-10-02.txt
```

자기 메모를 쓴다면 마지막 경로만 바꿉니다.
