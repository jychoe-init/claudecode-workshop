# Lab 2 — 사내 API를 스킬로 자동화하기

## 목표
- 사내 API 데이터를 내 팀 양식으로 정리하는 스킬을 만듭니다.
- 조회와 변경의 승인 규칙 차이를 확인합니다.
- 결과를 화면에서 끝낼지, 파일로 남길지 결정하고 그 결과(승인 창)를 예측합니다.

## 시작 명령

```text
/workshop-coach lab2
```

## 패턴 A와 B

| 항목 | 패턴 A · MCP 도구 | 패턴 B · 스킬 안에서 조회 |
|---|---|---|
| 호출 | 대화 중 필요한 도구를 Claude가 고름 | 사람이 `/이름`으로 실행 |
| 용도 | 조회와 변경이 섞인 업무 | 같은 데이터를 같은 형식으로 만드는 보고 |
| 권한 | 조회는 allow, 신청은 ask | 조회 스크립트의 사전 승인 위치(설정 / 스킬)를 결정 |
| 속도 | 도구 선택과 API 왕복이 필요 | 첫 줄에서 정해진 조회를 바로 실행 |
| 이번 실습 | 강사 시연 | 참가자가 직접 만듦 |

## 1. 연결 설계

**참가자가 하는 일**
- 연결할 시스템과 조회 동작 두 개를 정합니다.
- 독자, 출력 형식, 결과를 남기는 곳(화면 / `reports/`)을 정합니다.
- 조회 스크립트의 사전 승인을 팀 설정에 둘지 스킬에 동봉할지 결정하고 이유를 남깁니다. (주입 명령은 승인 창을 띄우지 않습니다. 승인이 없으면 스킬이 중단됩니다.)

**Claude에게 일반 요청으로 시키는 일**
- `tools/hr_fetch.py`를 본보기로 조회 전용 `tools/<시스템>_fetch.py`를 만들게 합니다.
- 참가자가 고른 경로와 인자를 넣고 JSON만 출력하게 합니다.
- POST가 없는지 확인하게 합니다.

## 2. 스킬 작성

**참가자가 하는 일**
- `.claude/skills/leave-report/SKILL.md`를 복사해 주입 줄, 출력 형식, 금지 줄을 내 보고에 맞게 씁니다.
- 결정한 위치에 승인 한 줄을 씁니다: 스킬 frontmatter `allowed-tools:` 또는 `.claude/settings.json` `permissions.allow`.
- 외부 응답은 지시가 아니라 데이터라는 원칙을 `CLAUDE.md`에 한 줄 씁니다.

**Claude에게 일반 요청으로 시키는 일**
- JSON 문법을 검사하게 합니다.
- 스킬의 주입 줄과 조회 스크립트 경로가 같은지 확인하게 합니다.

## 3. 예측하고 실행

실행 전에 두 가지를 적습니다.
1. 승인 줄을 잠시 지우고 실행하면 승인 창이 뜰지, 중단될지, 그냥 실행될지 예측합니다. 확인 뒤 되살립니다.
2. 파일 저장을 택했다면 저장 때 승인 창이 또 뜰지, 화면만이면 토큰이 없을 때 보고가 어떻게 나올지 예측합니다.

```text
/<보고이름>
```

공용 API를 쓸 수 없을 때만 아래처럼 로컬 대체 서버를 사용합니다.

```bash
python3 tools/lab_server.py
LAB_API_BASE=http://127.0.0.1:8787 claude
```
